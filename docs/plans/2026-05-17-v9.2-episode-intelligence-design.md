# CSR v9.2 — Episode Intelligence + Agent Hook

> **Goal:** Make CSR the first tool in the ecosystem to use agent hooks, with structured episode capture that answers "what happened last session?" reliably.
>
> **Time budget:** 1 hour implementation
> **Version:** 9.2.0

---

## Problem Statement

CSR stores *events* (tools used, files touched) but not *episodes* (what was attempted, what succeeded, what remains). Session start injection is a plain text blob that Claude treats as ambient noise. claude-mem (76k stars) solved structured episodes with their `session_summaries` table (`request/investigated/learned/completed/next_steps`). CSR needs to match and exceed this.

Additionally, no tool in the ecosystem uses Claude Code's `"agent"` hook type or `asyncRewake` capability. CSR can be first.

## Architecture

```
Session N (active)                    Session N+1 (next start)
─────────────────                     ─────────────────────────
                                      
Stop hook fires (every response)      SessionStart fires TWO hooks:
  │                                     │
  ├─ Import transcript (existing)       ├─ Hook 1: SYNC command (<100ms)
  ├─ Extract structured episode         │   └─ csr-engine hook session-start
  │   {request, investigated,           │       Prints: continuity detection,
  │    completed, next_steps,           │       anti-patterns, lightweight context
  │    outcome, blockers}               │       (EXISTING behavior, unchanged)
  └─ Store as tagged reflection         │
      tag: session_episode              ├─ Hook 2: ASYNC agent (asyncRewake)
                                        │   └─ Prompt reads recent episodes
                                        │       from CSR MCP tools, reasons
                                        │       about patterns, generates
                                        │       proactive briefing
                                        │   └─ Wakes model when done (~2-3s)
                                        │       Injects as additionalContext
                                        └─ User sees ZERO delay
```

## Feature 1: Structured Episode Capture (Stop Hook)

### Data Model

Episodes are stored as JSON in the existing reflection storage (no schema migration needed):

```json
{
  "schema": "csr_episode_v1",
  "session_id": "abc-123",
  "project": "claude-self-reflect",
  "timestamp": "2026-05-17T14:30:00Z",
  "request": "Fix the auth middleware regression",
  "investigated": ["src/auth/middleware.rs", "tests/auth_integration.rs"],
  "completed": "Fixed token validation, added regression test",
  "next_steps": "Deploy to staging, check metrics",
  "blockers": null,
  "outcome": "success|partial|failed|interrupted",
  "error_signatures": ["E0308", "connection refused"],
  "tools_used": ["Edit", "Bash", "Read"],
  "files_modified": ["src/auth/middleware.rs"],
  "message_count": 24,
  "duration_minutes": 25
}
```

### Extraction Logic (Heuristic, No LLM Call)

All extraction happens in the Stop hook (<10ms):

- **request**: First user message in transcript (truncated to 200 chars)
- **investigated**: Union of files from Read/Glob tool_use blocks (deduplicated)
- **completed**: Last assistant text message before stop (truncated to 300 chars, strip tool calls)
- **next_steps**: Extracted if last message contains "next", "todo", "remaining", "then" patterns; null otherwise
- **outcome**: `"interrupted"` if message_count < 3, `"failed"` if last messages contain error patterns, `"success"` if completion language detected, `"partial"` as default
- **error_signatures**: Collected from tool_result blocks containing error/Error/panic/FAIL patterns
- **tools_used**: Deduplicated tool names from tool_use blocks
- **files_modified**: Files from Edit/Write tool_use inputs
- **message_count**: Count of messages in transcript
- **duration_minutes**: Derived from first/last message timestamps

### Storage

- Stored via `engine.storage().store_reflection()` (existing API)
- Tags: `["session_episode", "schema_v1", "project_{name}", "conv_{session_id}"]`
- Rolling: Each Stop event overwrites the previous episode for the same session (upsert by conv tag)
- The episode is also embedded for semantic search (existing embedding pipeline)

`csr-engine/src/hooks/stop.rs` — add `extract_episode()` and `store_episode()` functions

## Feature 2: Agent Hook at SessionStart (asyncRewake)

### Hook Registration

In `settings.json`, SessionStart gets a second hook entry:

```json
{
  "hooks": {
    "SessionStart": [
      {
        "matcher": "startup|resume|compact",
        "hooks": [
          {
            "type": "command",
            "command": "/usr/local/bin/csr-engine hook session-start"
          }
        ]
      },
      {
        "matcher": "startup|resume",
        "hooks": [
          {
            "type": "agent",
            "prompt": "You are CSR Episode Analyst. Search recent session episodes and generate a proactive briefing.\n\nUse the csr_reflect_on_past tool to search for recent session episodes in this project.\nSearch query: 'session_episode schema_v1'\n\nThen analyze the episodes and produce a brief (under 150 words) that tells the user:\n1. What they worked on recently and how it went\n2. Any patterns (repeated errors, ongoing work across sessions)\n3. Anything left unfinished that they might want to pick up\n\nBe specific, not generic. Reference actual file names, error messages, and outcomes from the episodes.\nIf no episodes are found, say 'No recent session episodes found — this is a fresh start.'\n\nFormat your output as a system message starting with '## Session Intelligence (CSR v9.2)'",
            "model": "claude-haiku-4-5-20251001",
            "timeout": 15,
            "async": true,
            "statusMessage": "CSR analyzing recent sessions..."
          }
        ]
      }
    ]
  }
}
```

### Why asyncRewake Is Not Used (Yet)

`asyncRewake` wakes the model on exit code 2 (error). For the initial release, we use `"async": true` which runs in background without blocking. The agent's output gets injected as `additionalContext` when it completes. If the model is already responding, the context arrives for the next turn.

Future: `asyncRewake` could be used to interrupt Claude with urgent findings ("you've hit this same error 5 sessions in a row").

### Why Agent Hook, Not Command

- A command hook prints text. Claude reads it passively.
- An agent hook has tools available. It can call `csr_reflect_on_past`, `csr_search_insights`, `get_recent_work`. It REASONS about what it finds.
- The agent can say "you've been debugging auth for 3 sessions — last session you identified the root cause was in middleware.rs line 47 but didn't finish the fix."
- No other tool in the ecosystem does this.

### File Modified

`csr-engine/src/hooks/install.rs` — add second SessionStart hook entry with agent type

## Feature 3: Episode-Aware MCP Search (Enhancement)

### Change

When `csr_reflect_on_past` returns results, if any result is a `session_episode` reflection, format it as structured episode data instead of raw text:

```xml
<episode project="claude-self-reflect" time="2h ago" outcome="partial">
  <request>Fix the auth middleware regression</request>
  <completed>Fixed token validation</completed>
  <next_steps>Deploy to staging</next_steps>
  <files>src/auth/middleware.rs</files>
</episode>
```

This makes episodes distinguishable from regular search results, both for the agent hook and for direct MCP tool usage.

### File Modified

`csr-engine/src/mcp/tools.rs` — modify result formatting for episode-tagged reflections

## Gemini Review Findings (Incorporated)

### Fixes Applied

1. **Episode GC clarity** — Stop fires every response (~24x/session). The upsert must DELETE the previous episode reflection for the same `conv_{session_id}` tag before inserting the new one. Not "overwrite" — explicit delete + insert to prevent search noise from stale versions.

2. **Agent hook fallback** — If agent hook times out (15s) or fails, the sync command hook already ran first and delivered lightweight context. No user sees a blank start. Add `eprintln!` logging in the sync hook to record when agent hook is expected to follow.

3. **Skip trivial sessions** — Agent hook should only fire on `startup|resume`, NOT `compact`. Compact events don't need a full briefing. Additionally, the agent prompt should handle "no episodes found" gracefully (already in the prompt).

4. **Outcome heuristic caveat** — ~15% mislabeling expected (e.g., 1-message success, multi-message partial). Acceptable for v9.2. Daemon enrichment (v9.3) upgrades outcomes with LLM reasoning via the existing 3-layer pipeline.

### Not Addressed (Future)

- **Privacy tags** (`<private>` exclusion) — claude-mem has this, CSR doesn't. Future v9.3 feature.
- **Multi-platform support** — Claude Code only for now. Schema-driven transcript ingestion is a v10 consideration.
- **asyncRewake** — Deferred. `async: true` is sufficient. asyncRewake's exit-code-2 interrupt model is fragile for session intelligence (could cause noisy interrupts).

## Risks

1. **Agent hook support maturity** — New Claude Code feature, community reports are sparse.
   Mitigation: Agent hook is async, so failure is silent. Fast command hook always runs first. Add stderr logging to track success rate.

2. **Heuristic episode quality** — Without an LLM, extraction is pattern-based (~85% accuracy).
   Mitigation: Good enough for MVP. Daemon enrichment (existing pipeline) upgrades episodes with AI narratives in v9.3.

3. **Episode storage bloat** — Stop fires every response.
   Mitigation: Explicit delete + insert by `conv_{session_id}` tag — exactly 1 episode per session at any time.

4. **Agent hook raw output leaking** — Community reports of `<system-reminder>` payloads leaking as raw text.
   Mitigation: Agent prompt instructs clean markdown output. Async delivery means even if formatting is off, it's additive context, not blocking.
