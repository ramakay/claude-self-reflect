## A. Blocking — correctness defects that can corrupt or lose memory

### A1. `Incomparable` history silently mints a positive supersession verdict
- **Where:** `codewitness/src/auditor.rs:245-256`
- **Defect:** a correctly stamped successor on an unrelated, rebased, squashed or abandoned branch is accepted as `Superseded(ContentOnly)`. Content verification proves that successor's bytes, not that it superseded the original witness. Caller-selected unrelated evidence converts a drift/unknown relationship into an affirmative receipt.
- **Do:** return the fallback verdict or an explicit abstention when ancestry is `Incomparable`. If content-only receipts are wanted at all, make them an explicit opt-in requiring independent lineage or `normalized_diff_id` evidence.
- **Verify:** new test in `codewitness/tests/adversarial.rs` constructing an unrelated branch and asserting abstention; `cargo test -p codewitness`.
- **Source:** Codex [high].

### A2. Ambiguous HEAD witnesses produce insertion-order-dependent verdicts
- **Where:** `csr-engine/src/dream/mod.rs:408-418`
- **Defect:** the ledger is grouped only by `(project,file,symbol)` and preserves row-id order; `h` is the first row found at HEAD. Multiple generations or extractor versions can legitimately record different spans/stamps for the same symbol at the same HEAD. Reversing insertion order flips an older witness from intact/reinstated to superseded — and because HEAD is a descendant, the selected successor can still receive a `GraphOrdered` receipt.
- **Do:** resolve HEAD truth through the selected complete current-extractor generation. If more than one distinct stamp remains for an anchor at HEAD, **abstain**.
- **Verify:** insert the same anchor twice in both orders, assert identical verdicts; assert abstention on conflicting HEAD stamps.
- **Source:** Codex [high].

### A3. One stale symbol demotes every memory from its conversation
- **Where:** `csr-engine/src/mcp/tools.rs:1653-1670`
- **Defect:** validity reduction takes any `Demote` hit as the verdict for the whole conversation; the partition then sinks every chunk carrying that conversation id, including unrelated live decisions and prose. Bounded overfetch followed by truncation can remove those correct chunks from results indefinitely.
- **Why blocking:** this is the user-visible failure the whole design promises cannot happen — correct memory suppressed on unrelated evidence.
- **Do:** bind validity to the specific chunk/anchor cohort. For mixed conversations, annotate without rank demotion unless every relevant anchor is demonstrably stale.
- **Verify:** fixture conversation with one stale anchor + one live decision; assert the live chunk keeps its rank.
- **Source:** Codex [high].

### A4. Merges launder concurrent edits into `GraphOrdered` — the strongest basis, for unrelated work
- **Where:** `codewitness/src/causal.rs:44-55`; doc gap at `codewitness/src/verdict.rs:64-67`; same predicate used in production at `csr-engine/src/dream/mod.rs:574-586`.
- **Verified directly:** `compare` returns `AncestorOf` whenever `merge_base(a,b) == a`. After branch1 and branch2 merge at M, a witness at A on branch1 *is* a genuine ancestor of M — so a successor stamped at or after the merge mints `GraphOrdered` even though the edit came from branch2 and never derived from A. **Ancestry is not derivation.** The `ContentOnly` doc lists squash, rebase, cherry-pick and unrelated-branch as the `Incomparable` causes and **does not mention merges at all**, which is why this was not designed for.
- **Why it outranks A1:** A1 mints the *weak* basis on unrelated evidence. This mints the *strong* one, through an ordinary merge workflow, which is the common case in any repo with branches.
- **Do:** ordering alone must not certify supersession. Require that the successor anchor be reachable from the witness *through the anchor's own change history* (path-scoped ancestry), or downgrade merge-reachable-only relationships to `ContentOnly`. Update the `verdict.rs` doc either way.
- **Verify:** fixture with two branches editing different functions, merged; assert the concurrent edit does not produce `GraphOrdered`.
- **Source:** Fusion panel (Opus seat), verified here.

### A5. The recap self-contamination guard is defeated by a leading `- ` or `> `
- **Where:** `csr-engine/src/extraction/provenance.rs:167-181`, tokens at `:71-80`; composer at `csr-engine/src/hooks/recap.rs:138,144,145`.
- **Verified directly:** `is_csr_emission` has three branches. Branch 1 matches 14 headers, none of which is a recap header. Branch 2 does `head.trim_start().strip_prefix("recap [")` — so **any** non-whitespace prefix defeats it. Branch 3 needs ≥2 of `EMISSION_FIELD_TOKENS`, which are `LAST:`, `NEXT:`, `TODOS:`, `ANCHORS:`, `CONTINUED FROM [`, `Past session [`, `(outcome=`, `csr_reflect_on_past(` — while the composer emits `Settled: `, `Now: `, `Next: `. Rust `contains` is case-sensitive, so `Next:` does not match `NEXT:`. **A recap paragraph matches zero field tokens.** The prefix check is the only thing standing.
- **Consequence:** `- recap [3d ago]: …` in a bullet list, or the assistant quoting the recap back with `> `, is re-importable as corpus. The self-contamination loop that v10 was built to close is open for the v10.1 headline feature.
- **Do:** match the recap grammar anywhere in the leading window rather than only at position 0, and add the composer's own clause labels to the token set. Then add the property test from C9 — it would have caught this.
- **Note:** the existing guard tests at `provenance.rs:252-285` only exercise composer-shaped strings, which is exactly why this survived — an instance of the §E failure pattern inside the guard for the feature that pattern is about.
- **Sibling variants found independently by other seats, same root cause:** `**recap [1d]:**` (markdown emphasis) defeats the prefix match; `recap ［` with a fullwidth U+FF3B bracket defeats it; and any preamble pushing `recap [` past `HEADER_WINDOW` defeats it, because `trim_start()` is applied to the *windowed slice*, not the full text. Fix the root cause — position-anchored prefix matching plus a token list missing the composer's own labels — not the individual strings.
- **Source:** Fusion panel — Opus seat named the bullet/quote form, Gemini the bold form, DeepSeek the window/Unicode forms, GPT the bytes-vs-chars bound. Verified here.

## B. Blocking — claim integrity

### B1. `CHANGELOG.md:67` publishes a bare `1.000 / 1.000`
- **Verified directly:** `CHANGELOG.md:67` reads `1.000 / 1.000 over 13,626 beliefs.` with no caveat, while `csr-engine/eval-kit/t4/README.md:46` says recall 1.0 is **guaranteed by construction**, `:152` repeats it for F1, and `:156` says precision 1.000 is **"unfalsified, not proven"** because the corpus has zero reverts.
- **Do:** in the same bullet, carry all four facts — recall is structural, corpus contains zero reverts, precision is unfalsified not proven, pointer to the eval-kit README — or delete the number from the release note entirely.
- **Verify:** re-read the bullet; it must not be quotable as a bare success metric.
- **Source:** Grok [blocking], digest 6.3, re-verified here.

### B2. The dream benchmark does not run the dream algorithm
- **Where:** `codewitness/src/bin/codewitness.rs:624-678`
- **Defect:** it predicts staleness by checking whether any later sampled tag has a different stamp, with ground truth derived from the final tag. It never invokes `dream`, never reads persisted verdicts, and has no production-equivalent ancestry or abstention logic. An A→B→A sequence counts stale even though production reinstates it.
- **Do:** run the actual dream pipeline at each evaluation snapshot and score persisted verdicts against independently constructed held-out truth. Do not expose future tag maps to the prediction. Until then, do not describe its output as a dream measurement anywhere.
- **Source:** Codex [high].

### B3. Prove the precision meter can move
- **Do:** build one synthetic or adversarial corpus containing deliberate reverts — the exact failure mode the rule exists to catch — and show the score drops below 1.0 on it.
- **Why:** with zero reverts in the real corpus, that confusion-matrix cell is empty by corpus, not by proof. A gate that cannot fail is not a gate — this project's own stated lesson, twice.
- **Source:** Grok [blocking]; follows from B2.

### B4. "Append-only" is a naming convention, not an enforcement
- **Where:** `csr-engine/src/storage/migrations.rs:756-769` (plain DDL, no triggers, no read-only attachment), `witness_ledger.rs` (module exposes insert+query only).
- **Defect:** nothing at the SQL layer rejects `UPDATE` or `DELETE`. There are zero raw mutations in the tree today; the risk is tomorrow's contributor, a careless `execute_batch`, or a raw `sqlite3` session. **This has already happened once here** — PR #279's unconditional drop wiped witness rows on every process start, fixed with a shape probe rather than a structural guard.
- **Do (blocking):** `BEFORE UPDATE` / `BEFORE DELETE` triggers raising `ABORT` on `witness_ledger` **and** `witness_verdicts`. Otherwise stop calling it append-only in CHANGELOG, CLAUDE.md and the three module docs — "append-preferring event log" is the honest name.
- **Do (follow-on, not blocking):** hash chain or per-generation Merkle binding verified by `status --deep`, since triggers do not stop file-level surgery. Document the real threat model: the owner of the SQLite file can always destroy trust.
- **Verify:** a test that attempts `UPDATE`/`DELETE` on both tables and asserts rejection. Note this test is currently *impossible to write* — that is the finding.
- **Source:** Grok [blocking], digest 6.1.

### B5. 747 self-contaminated conversations are still in the corpus
- **Defect:** the shared sanitizer prevents new contamination; it does not clean what is already embedded. 747 conversations carry `csr_reflect_on_past` output (MEMORY_MANIFEST ×120, CSR PICKUP ×72, EPISODE INDEX ×66).
- **Do:** run the clean-DB reimport (also rescopes the 985 sidechain files), **or** state the contamination as known open debt in the release note itself — not only in the internal audit.
- **Source:** Grok [blocking]; carried open from the prior session.

**Method gates worth adopting regardless of ship decision**
- **Revert mining**: `git log --grep='^Revert '` across ~20 public repos yields thousands of real reverts with free ground truth. Hours of work, and it attacks the empty stratum directly — this is the cheapest path to B3.
- **A poison test per published metric**: deliberately break the thing, assert the number drops. A metric that cannot be made to fail on demand does not belong in release notes.
- **Wilson lower bound**, never a point estimate of 1.0.
- **Pre-registered abandon rule** splitting *mechanical* false-stales (CRLF, span shift — fixable) from *semantic* ones (comment inversion, moved-and-modified — hashing cannot reach them). Note the second class implies "no LLM on the verdict path" cannot hold for the demote channel.
- **Denominator discipline**: author the evaluation manifest independently and LEFT JOIN predictions onto it, so the denominator is never built by the system under test. The panel localizes the most likely third rig to cohort construction in the eval SQL — inner joins dropping unlinked rows, "latest generation" selecting only `status='complete'`, missing output scored as not-applicable rather than false negative. ## C-ter. Panel claims that are WRONG — do not action these

Recorded so nobody re-opens them. All verified against the source.

- **Annotations never enter embedded text.** `validity_note` renders `[stale anchor]`/`[evolved]` **at query time** (`mcp/tools.rs:1673-1686`). Every "vector drift", "re-embedding contamination" and "annotation poisoning" finding is void. Residual real risk: the rendered string enters the assistant's context and can be re-imported — which is A5, not this.
- **Symbol collision is fixed in production.** `backfill.rs:1323,1641` pass `qualified_symbols`. Only the kernel API takes free-form symbols.
- **Worktree evidence does not mint receipts.** `successor_is_valid` rejects any non-`Committed` successor, so `receipt()` always cites a real commit. The worktree tier applies to the *witnessed* side. Several panel findings and one panel "blocker" rest on this error.
- **`stamp_normalized` does not strip comments** — whitespace-only normalization over four ASCII bytes, no language grammar. The `// SAFETY:` false-`Intact` scenario cannot occur. Relatedly, stamp kind *is* recorded: the `b3:`/`b3n:` prefix, parsed by `Stamp::kind()`.
- **The 31 mutants.** `CHANGELOG.md:95-96` says all 31 **missed** mutants were killed — 31 survivors of a larger run, not the total. The panel's top-ranked "third tautology" candidate is a misreading of the release note. C1 still stands on its own evidence.
- **The duplicate `witness_generations` DDL is test-only** (`chunk_binding.rs:643` is inside a `#[cfg(test)]` helper). Only "tests validate states production rejects" survives.
- **Worktree witnesses are not unbound** — `stamp_with_kind` sets `at = repo.head_id()`. That is schema laxity (see P6), not a write-path defect.
- **`publish = false` means the crate cannot be published at all**, and `0.1.0-alpha.1` does not permanently freeze an API under pre-1.0 semver. Only one panelist got this right; discount the others' urgency here.

## E. Standing posture, from the base rate

Two measurements in this project were built so they could not fail, and both were caught by adversarial review rather than by its own tests. The correct posture toward the remaining numbers:

- Any bare precision/recall/coverage figure without a corpus-limit and construction analysis → not publishable.
- Dogfood counts (545 supersessions, 11,192 witnesses) → existence and idempotency evidence only, never quality.
- Type-level tiers, kill switches, fail-open defaults → legitimately higher prior; they are properties, not scores.
- Mutation testing → meaningful on pure functions only, and only on modules actually in the mutants list.
- A four-digit test count → weak evidence, after fixture-green recap shipped visibly broken against the live corpus.
- The generator must never judge its own measurement. A gate that cannot fail is not a gate.
